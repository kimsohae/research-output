# Confluence Report

## Purpose

맥락을 모르는 사람이 나중에 읽어도 이해할 수 있는 자립적인 문서를 만든다.

독자가 다음을 이해할 수 있어야 한다.

- 왜 조사했는가
- 무엇을 알게 되었는가
- 어떤 근거가 있는가
- 무엇을 의미하는가
- 무엇을 결정하거나 실행해야 하는가

## Reader model

독자가 현재 작업 맥락을 모두 안다고 가정하지 않는다.

그러나 불필요한 배경 설명으로 문서를 늘리지 않는다.

프로젝트 내부 용어나 전문 용어는
처음 읽는 사람이 이해하는 데 필요한 만큼만 설명한다.

## Recommended structure

# [리서치 주제를 나타내는 제목]

## 한눈에 보기

문서 전체를 읽지 않아도 핵심을 이해하게 한다.

다음 순서를 우선한다.

**결론**

가장 중요한 결론을 1~3문장으로 작성한다.

**왜 중요한가**

제품, 프로젝트, 사용자 또는 의사결정에 어떤 영향을 주는지 설명한다.

**결정 또는 다음 행동**

필요하다면 현재 필요한 결정이나 행동을 명시한다.

## 배경

간결하게 설명한다.

- 왜 조사를 시작했는가
- 어떤 질문에 답하려 했는가
- 범위는 어디까지인가

이미 널리 알려진 배경은 반복하지 않는다.

## 핵심 발견

중요한 Finding부터 설명한다.

각 발견은 다음 흐름을 따른다.

1. 무엇을 발견했는가
2. 핵심 근거는 무엇인가
3. 왜 중요한가
4. 어떤 제한이 있는가

가능하면 원본 Finding ID 또는 source를 추적 가능하게 유지한다.

## 종합 해석

개별 발견을 함께 보았을 때의 패턴과 결론을 설명한다.

Finding을 단순히 다시 나열하지 않는다.

다음을 고려한다.

- 여러 근거가 같은 방향을 가리키는가
- 서로 충돌하는 결과가 있는가
- 예상과 달랐던 것은 무엇인가
- 기존 판단을 바꿔야 하는가

## 제안

권고할 행동이 있을 때 작성한다.

가능하면 다음을 포함한다.

- 무엇을 할 것인가
- 왜 하는가
- 기대 효과
- 중요한 리스크나 전제

근거가 약하면 확정적인 표현을 피한다.

## 결정이 필요한 사항

실제 의사결정이 필요한 경우에만 작성한다.

결정할 내용을 명확한 질문 형태로 표현한다.

가능하면 선택지와 trade-off를 설명한다.

## 남은 질문

현재 리서치만으로 해결되지 않은 중요한 질문을 기록한다.

추가 조사가 판단을 어떻게 바꿀 수 있는지도 설명한다.

## 출처

주요 출처를 정리한다.

중요한 수치나 주장은 원본 출처까지 추적 가능해야 한다.

## Writing principles

### 결론을 숨기지 않는다

긴 배경 뒤에 결론을 배치하지 않는다.

### 설명 없이 bullet만 나열하지 않는다

항목 사이의 관계가 중요하면 문장으로 설명한다.

### 근거와 해석을 구분한다

데이터가 보여주는 것과 작성자의 해석을 분리한다.

### 한 문단은 한 역할을 담당한다

한 문단에 여러 주제를 과도하게 섞지 않는다.

### 헤딩만 읽어도 흐름이 보이게 한다

나쁨:

```text
분석 결과
```

좋음:

```text
신규 사용자의 첫 주 이탈이 증가했다
```

### 모든 정보를 본문에 넣지 않는다

의사결정이나 이해에 영향을 주지 않는 세부 정보는 부록이나 출처로 보낸다.

## Do not

- 과도한 bullet 나열
- 근거 없는 단정
- 의미 없는 "인사이트"
- 같은 결론의 반복
- 조사 과정에 대한 메타 설명
- research-output에 없는 사실 추가
- Slack처럼 지나치게 압축된 문장

## Final check

- 이 문서만 처음 보는 사람도 조사 목적을 이해하는가?
- 첫 화면에서 가장 중요한 결론을 알 수 있는가?
- 주요 결론마다 근거를 확인할 수 있는가?
- 사실과 해석이 구별되는가?
- 다음에 무엇을 해야 하는지 알 수 있는가?
- 한 달 뒤 다시 읽어도 맥락을 이해할 수 있는가?

아니라면 수정한다.
