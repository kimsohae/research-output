# Slack Report

## Purpose

Slack에서 짧은 시간 안에 다음을 파악할 수 있게 한다.

- 무슨 일이 있었는가
- 무엇을 알게 되었는가
- 왜 중요한가
- 무엇을 해야 하거나 결정해야 하는가

Slack에 전체 리서치를 복제하지 않는다.

상세 내용은 Confluence 또는 원본 리서치로 연결한다.

## Default structure

**한 줄 결론**

가장 중요한 내용을 첫 문장에 쓴다.

**핵심 내용**

2~4개의 핵심 포인트만 전달한다.

**의미**

필요하면 현재 업무에 어떤 의미가 있는지 1~2문장으로 설명한다.

**액션 / 결정**

행동이나 결정이 필요하면 명확히 표시한다.

**상세**

문서가 있으면 링크한다.

## Template

```text
[한 줄 결론]

- 핵심 발견 1
- 핵심 발견 2
- 필요하면 핵심 발견 3

따라서 [현재 업무에 갖는 의미].

다음 액션: [필요한 행동 또는 결정]

상세: [문서 링크]
```

## Writing principles

### 결론부터 쓴다

다음으로 시작하지 않는다.

- 조사해보았습니다.
- 몇 가지 내용을 확인했습니다.
- 관련 내용을 공유드립니다.

바로 결과를 전달한다.

### 하나의 메시지에는 하나의 중심 목적을 둔다

다음 중 무엇인지 분명해야 한다.

- 정보 공유
- 결정 요청
- 문제 제기
- 진행 상황 보고

여러 목적이 섞이면 가장 중요한 목적을 먼저 보여준다.

### 세부 근거를 모두 넣지 않는다

결론의 신뢰성을 판단하는 데 필요한 핵심 근거만 남긴다.

상세한 근거는 문서로 연결한다.

### 중요한 숫자는 남긴다

나쁨:

```text
사용자 이탈이 크게 증가했습니다.
```

좋음:

```text
신규 사용자의 7일 내 이탈률이 31%에서 44%로 증가했습니다.
```

### bullet을 과도하게 사용하지 않는다

기본적으로 2~4개면 충분하다.

5개 이상 비슷한 bullet이 필요하면
문서로 분리할 필요가 있는지 검토한다.

### 모바일에서도 빠르게 읽혀야 한다

표는 기본적으로 사용하지 않는다.

긴 문단을 피한다.

### 강조를 남용하지 않는다

굵은 글씨는 다음 용도에 제한한다.

- 결론
- 요청
- 결정
- 놓치면 안 되는 일정

### 장식용 이모지는 기본적으로 사용하지 않는다

조직의 기존 관례가 있을 때만 사용한다.

## Report modes

### 정보 공유

결론
→ 핵심 발견
→ 의미
→ 상세 링크

### 의사결정 요청

결정할 것
→ 추천안
→ 추천 이유
→ 주요 trade-off
→ 필요한 시점
→ 상세 링크

### 문제 / 리스크

문제
→ 영향
→ 현재 파악된 원인
→ 진행 중인 대응
→ 필요한 도움 또는 결정

### 진행 상황

현재 상태
→ 이전 보고 이후 변화
→ 리스크
→ 다음 단계

## Length

가능하면 한 화면에서 핵심을 파악할 수 있게 한다.

그러나 중요한 조건이나 불확실성을 지우면서까지 줄이지 않는다.

길어지면 다음처럼 분리한다.

Slack:
- 결론
- 핵심
- 액션

Confluence:
- 배경
- 전체 근거
- 분석
- 세부 내용

## Do not

- 리서치 과정 설명
- 장황한 배경
- 비슷한 bullet 5개 이상
- Confluence 본문 복사
- "참고 부탁드립니다"만 있는 모호한 요청
- 결론보다 앞서는 긴 인사말
- 원본에 없는 주장
- 중요하지 않은 세부 수치 나열

## Final check

- 첫 두 문장 안에 핵심 결론 또는 요청이 있는가?
- 30초 안에 의미를 이해할 수 있는가?
- 무엇이 중요한지 분명한가?
- 행동이 필요하면 무엇을 해야 하는지 분명한가?
- 상세 정보로 가는 경로가 있는가?
- research-output의 의미를 왜곡하지 않았는가?

아니라면 수정한다.
